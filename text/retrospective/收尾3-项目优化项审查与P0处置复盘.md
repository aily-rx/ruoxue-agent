## 本次处置明细

### P0-1 工具按需绑定 —— 实验推翻，不做

**假设**：闲聊首字延迟（服务器 3.2~4.0s vs 本地热态 1.0~2.1s）来自 DeepSeek 绑 5 工具后的"首内容 token 前空 chunk 阶段"（0.9~2.7s）。

**实验**（A/B，4 个闲聊问题 × 无工具/5工具，正确读取 `ChatGenerationChunk.message.content`）：

| 组 | 首内容 token 延迟 |
|---|---|
| 无工具 | 0.70 / 0.70 / 2.38 / 1.22s（均值 1.26s）|
| 绑 5 工具 | 1.10 / 0.70 / 1.06 / 调工具无文本（均值 0.95s）|

**结论**：无显著差异，方差（0.7~2.4s）完全淹没组间差；且电影推荐题在绑工具组真实触发了工具调用。空 chunk 阶段是 DeepSeek 服务端预处理，与工具 schema 无关。关键词路由会白加误判风险 → **不做**。残余首字延迟归因为 API 侧，后续靠服务器日志（`llm call retry` 排查）+ 接受现状。

### P0-2 健康检查 llm_available 真实化（已实现）

- `agent_graph.ping_llm(timeout=2.5)`：无 API key 快速 False（不发请求）；否则发 `max_tokens=1` ping，异常吞掉返回 False
- `routes._check_llm_available()`：60s TTL 缓存，health 端点高频调用不重复打 API
- 新增 4 个单测（无 key 快速路径 / LLM 报错 / TTL 内复用 / TTL 过期重探）

### P0-3 裸 print → 结构化日志（已实现）

19 处 print 处置：`main.py` 6 处（启动/预热状态）、`tts_service.py` 6 处（Edge TTS 成败）、`chroma_memory.py` 2 处（存取失败）、`rag_service.py` 1 处（FAISS 索引）、`routes.py` 2 处（分片合成失败/Chroma 写入失败）→ 各模块 `_logger`（JSON 格式，可被 Loki/ELK 索引）；`agent_graph.py` 2 处与既有 `_logger.info` 埋点重复 → 直接删除。

## 思维模式（面试可讲）

1. **先测量再优化**：首字延迟的三个候选原因（工具绑定/标签门槛/冷启动构造）逐一 A/B 实测，用数据推翻"工具按需绑定"这个直觉上正确的方案，省下一次有误判风险的改造。
2. **健康检查是真实信号不是安慰剂**：`llm_available=True` 写死让监控失去意义；探测要带超时 + 结果缓存，防止监控本身拖垮系统。
3. **日志管道统一**：项目已有 JSON 结构化日志，print 绕过管道会让 request_id 追踪断链——可观测性基础设施的价值在于全量覆盖。

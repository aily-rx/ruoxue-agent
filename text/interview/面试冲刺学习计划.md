### P0-1 Transformer 与 Attention

- **面试官怎么问**：self-attention 的计算过程？为什么需要位置编码？多头注意力的作用？为什么用缩放点积？
- **项目对应**：无直接代码对应，但流式生成（SSE 逐 token）依赖 decoder 自回归架构——可以衔接"为什么 LLM 是逐 token 生成的"
- **2 分钟讲述框架**：输入 embedding → Q/K/V 三个线性投影 → 点积算注意力分数 → 除以 √d_k 缩放（防 softmax 饱和）→ softmax 归一 → 加权求和 → 多头并行捕捉不同子空间 → 残差 + LayerNorm → 位置编码注入顺序信息（RoPE/正弦）
- **常见追问**：为什么缩放 √d_k？（维度大时点积方差大，softmax 梯度消失）；位置编码为什么重要？（自注意力无序）

### P0-2 Tokenizer（BPE）

- **怎么问**：中文怎么分词？BPE 的原理？token 数和字数什么关系？
- **项目对应**：中文场景直接相关——`jieba` 分词（BM25 用）、LLM 的 tokenizer 是 BPE 不是 jieba
- **2 分钟框架**：BPE = 从字符开始，统计相邻对频率，反复合并最高频对，直到词表上限；中文"若雪"可能被切成 2~3 个 token（字节级 BPE）；token 计价按 token 不按字
- **追问**：为什么中文 token 化效率低？（常用字多，单字 token 占比高，同样意思更多 token → 更贵）

### P0-3 温度 / 采样 / 上下文窗口

- **怎么问**：temperature 调低会怎样？top_p 是什么？上下文超了怎么办？
- **项目对应**：`LLM_TEMPERATURE=0.7`（config.py）；`LLM_MAX_TOKENS=8192`
- **2 分钟框架**：temperature 缩放 logits 后再 softmax（低=更确定，高=更随机）；top_p 只保留累积概率 p 内的词；上下文窗口 = 输入+输出总 token 上限；超长处理三件套：截断（丢最早）、摘要（压缩）、滑动窗口（项目 `MAX_HISTORY_TURNS=20`）
- **追问**：工具调用场景温度该高该低？（低——工具参数要精确）；为什么 streaming 能快？（首 token 延迟而不是全量等待）

### P0-4 Function Calling / Tool Use

- **怎么问**：模型怎么知道要调工具？schema 怎么传？工具结果怎么回填？
- **项目对应**：`agent_graph.py` 的 `bind_tools(AGENT_TOOLS)` → LangGraph ToolNode 执行 → ToolMessage 回填（全链路都有代码）
- **2 分钟框架**：工具声明（name/description/parameters JSON Schema）随请求发给模型 → 模型输出结构化 `tool_calls`（含参数）→ 应用层执行工具 → 结果作为 ToolMessage 回填 → 模型基于结果继续生成——**模型只负责"决定调哪个"，不负责"执行"**
- **追问**：工具调用失败怎么办？（项目答案：返回结构化错误串 + 防幻觉指令，让 LLM 决定）；多个工具并行调用？（`tool_calls` 数组）

### P0-5 ReAct 与 Agent 循环

- **怎么问**：ReAct 是什么？Agent 循环怎么设计的？和 Plan-and-Execute 区别？
- **项目对应**：LangGraph StateGraph：`START → agent → should_continue → tools → agent … → END`（完整代码）
- **2 分钟框架**：ReAct = 推理（Reasoning）与行动（Acting）交替：Thought → Action → Observation 循环；LangGraph 把它结构化为 节点 + 条件边；项目用 `should_continue` 判断"末条消息是否含 tool_calls"决定去 tools 还是 END
- **追问**：循环失控怎么办？（`MAX_TOOL_ROUNDS=5`，短板④）；为什么有时 Agent 会反复调工具？（Observation 不满足预期 → 再 Thought——防不住就用上限兜底）

### P0-6 RAG 全流程 + 评估

- **怎么问**：RAG 完整流程？chunk 怎么切？检索质量怎么证明？
- **项目对应**：**最强项**——`rag_service.py` 全链路 + 评估体系
- **2 分钟框架**：加载 → 分块（500 字 + overlap）→ embedding → 向量存储 → 检索（混合：向量 + BM25 + RRF）→ 注入上下文 → 生成；评估分两层：检索层（Recall@k/MRR，50 题基线 0.78）+ 生成层（RAGAS faithfulness 0.905）
- **追问**：见 Day 3 追问弹药（RRF k=60、0.95 为何变 0.78、为何不上 rerank）

### P0-7 向量数据库选型

- **怎么问**：Chroma / FAISS / Milvus / pgvector 怎么选？
- **项目对应**：Chroma（长期记忆）+ FAISS（知识库索引）
- **2 分钟框架**：FAISS = 库不是服务（进程内，IndexFlatIP 精确检索，IVF/HNSW 近似加速）；Chroma = 轻量向量数据库（持久化 + 元数据过滤）；Milvus = 分布式（海量数据/高并发）；pgvector = 复用 PostgreSQL（有现成 PG 时）；**选型依据：数据量、并发、运维成本**——单机项目 Chroma/FAISS 够用
- **追问**：FAISS 的 IndexFlatIP 是什么？（内积索引，配合 L2 归一化等价余弦相似度——项目细节）

### P0-8 流式（SSE vs WebSocket）与异步

- **怎么问**：为什么用 SSE 不用 WebSocket？流式中断怎么办？
- **项目对应**：`routes.py` 的 StreamingResponse + `ChatClient.ts` 的 fetch ReadableStream 解析
- **2 分钟框架**：SSE = 单向文本流（服务端 → 客户端），HTTP 之上、自动重连、兼容性好；WebSocket = 双向二进制、需握手/心跳；**LLM 对话是单向推送场景，SSE 够用**；异步：FastAPI async generator + `stream_mode="messages"` 逐 chunk 转发
- **追问**：SSE 的坑？（项目实际踩过：event 行和 data 行跨 chunk 拆分 → `currentEvent` 必须声明在循环外——有回归测试）；前端怎么解析？（ReadableStream + TextDecoder + 按行缓冲）

### P0-9 结构化输出（JSON mode vs 正则约束）

- **怎么问**：怎么保证 LLM 输出符合格式？JSON mode 和正则约束取舍？
- **项目对应**：`EMOTION_TAG_RE` 正则提取 `[EMOTION: happy|0.5]` 标签（先写后读：正则定义在 emotional_agent.py）
- **2 分钟框架**：方案对比——JSON mode（模型层保证合法 JSON，但可能不匹配 schema 细节）/ 正则约束（零成本、流式可用、但脆弱）/ 输出校验重试（最稳但贵）；项目取舍：情绪标签用正则（流式逐 token 提取，JSON mode 不适用流式中间态）
- **追问**：为什么不用 JSON mode？（流式场景需要边生成边提取；标签是单行前缀，正则足够且零延迟）

### P0-10 Prompt 工程（分层 / few-shot / CoT / 防注入）

- **怎么问**：system prompt 怎么设计？为什么分层？few-shot 有用吗？
- **项目对应**：四层 prompt（system 静态 + runtime 日期 + memory 检索 + skill 动态注入）+ `_PROMPT_INJECTION_GUARD`
- **2 分钟框架**：分层好处（静态可缓存、动态按需拼装、可维护）；few-shot（给示例约束输出格式，成本 = 示例 token）；CoT（复杂任务让模型先推理再回答）；防注入（外部内容与指令隔离——项目 `<external_content>` 包装 + prompt 安全准则双保险）
- **追问**：动态注入的 skill 系统本质是什么？（关键词匹配 → 动态 prompt 编排）

### P1-11 混合检索（BM25 + RRF）

- **怎么问**：纯向量检索的盲区？为什么用 RRF 而不是分数相加？
- **项目对应**：`search_hybrid`——向量 top-20 + BM25 top-20 → RRF 融合（k=60）
- **2 分钟框架**：向量管语义（同义替换）、BM25 管精确（专有名词/ID/代码）；分数不可比（余弦 0~1 vs BM25 词频几十）→ RRF 只看排名：`score = Σ 1/(60+rank)`；两路都靠前的片段融合分最高
- **追问**：k 为什么 60？（论文标准值，让排名差异带来的分数差异不过大）；BM25 中文怎么做？（jieba 分词 + 小写 + 纯标点过滤——`_tokenize`）

### P1-12 评估体系（Recall / MRR / RAGAS）

- **怎么问**：怎么证明检索好？MRR 和 Recall 区别？RAGAS 指标含义？
- **项目对应**：50 题评估集 + 四指标 + RAGAS 三指标（真实数字）
- **2 分钟框架**：Recall@k = 答案进前 k 的比例；MRR = 答案排名的倒数均值（惩罚排太靠后）；RAGAS：faithfulness（编造）/ answer_relevancy（跑题）/ context_precision（上下文支撑）；**评估集是镜子不是奖状**——20 题 0.95 是样本量高估，50 题 0.78 才可信
- **追问**：评估集怎么保证质量？（fragment 原文校验脚本）；relevancy 为什么低？（无信息类分组 + 中文 judge 限制）

### P1-13 记忆系统（短期 + 长期）

- **怎么问**：为什么长期记忆用向量库不塞上下文？什么时候该写入？
- **项目对应**：`memory.py`（dict 滑动窗口 20 轮）+ `chroma_memory.py`（Chroma 语义检索）
- **2 分钟框架**：短期 = 当前会话（窗口截断防超长）；长期 = 跨会话语义检索（只取相关片段进上下文——省 token + 保相关性）；写入策略：每轮对话结束异步写入（fire-and-forget）
- **追问**：Chroma 检索不到相关记忆怎么办？（距离阈值 1.5 过滤，空则不带记忆上下文）

### P1-14 四层容错

- **怎么问**：工具失败？循环失控？LLM 超时？
- **项目对应**：短板④ 完整实现
- **2 分钟框架**：工具级（try/except 返回结构化错误 + 防幻觉指令）→ 超时（httpx timeout + 文件大小上限）→ 循环上限（`MAX_TOOL_ROUNDS=5` 强制 END）→ LLM 重试（tenacity 指数退避 3 次，reraise 不吞异常）
- **追问**：重试为什么指数退避？（限流场景等一会再试成功率更高）；防幻觉指令为什么有效？（LLM 默认倾向编造补全，显式指令压住）

### P1-15 可观测性（tracing）

- **怎么问**：回答错了怎么排查？慢在哪段？
- **项目对应**：短板⑤——request_id 贯穿 + 四阶段 JSON 埋点（start/chroma/skill/done 带耗时）+ 重试 WARNING 日志
- **2 分钟框架**：request_id 入口统一生成（X-Request-Id 响应头）→ 每阶段日志带 id + duration_ms → 按 id 过滤拼出全链路 → 级别即信号（INFO 正常/WARNING 重试）→ JSONFormatter 可被 Loki/ELK 索引
- **追问**：为什么日志不记检索全文？（只记长度——防日志膨胀）；和 LangSmith 区别？（自建可控 vs 外部工具，可增强）

### P1-16 缓存与成本

- **怎么问**：一次对话多少钱？怎么省钱？
- **项目对应**：短板⑥——LLM client 单例（lru_cache）+ embedding LRU 缓存 + 回复缓存（LRU+TTL，仅未走工具回复）+ usage 记账
- **2 分钟框架**：成本构成 = 输入 + 输出 token × 单价；优化三招：复用连接（单例）、避免重复推理（embedding 缓存）、避免重复生成（回复缓存——**只缓存确定性回复，走了工具的不缓存**，否则过时信息比不缓存更糟）
- **追问**：回复缓存的风险？（时间敏感问题——key 含当天日期 + TTL 10 分钟；测试隔离——use_cache 开关）

### P1-17 安全与 Prompt Injection

- **怎么问**：OWASP LLM Top 10 第一名是什么？怎么防？
- **项目对应**：短板⑦——read_file 白名单沙箱（resolve 后 is_relative_to）+ 外部内容隔离（`<external_content>` + 安全准则）+ 输出护栏（敏感模式过滤）
- **2 分钟框架**：直接注入（用户输入攻击）vs 间接注入（网页/文档里藏指令——**更危险**）；三层防护：文件边界（白名单）、内容边界（外部内容不可信声明 + prompt 准则双保险）、输出边界（过滤）；路径穿越防御（resolve 后检查，`../` 无效）
- **追问**：正则输出过滤的局限？（拦格式化的，拦不了自然语言——诚实说 demo 级，生产要 LLM 审核）

### P1-18 Human-in-the-loop

- **怎么问**：Agent 调工具要不要人工确认？怎么实现？
- **项目对应**：收尾②——LangGraph `interrupt()` + MemorySaver + SSE `tool_request` 事件 + `POST /api/hitl-confirm` + 超时默认拒绝
- **2 分钟框架**：工具节点 `interrupt()` 挂起 graph → SSE 发确认事件（含工具名/request_id）→ 前端确认条 → 确认端点 set_result → `Command(resume=bool)` 恢复；允许执行 / 拒绝注入 ToolMessage 让 LLM 转述 / 超时默认拒绝（防挂死）
- **追问**：为什么超时默认拒绝？（安全默认——不确定就当拒绝）；中断的 graph 状态放哪？（MemorySaver checkpointer，thread_id 每请求唯一）

## 五、最后一周的三条忠告

1. **别改代码了。** 现在改一行代码的边际价值，远低于把已有故事多讲一遍的边际价值。
2. **不完美的数字是武器，不是伤疤。** 0.78 不是"没做好"，是"50 题更可信"；relevancy 0.595 不是"跑题"，是"无信息类 + 中文限制的可解释现象"。主动讲 = 数据驱动；回避 = 心虚。
3. **面试是对话，不是考试。** 卡壳了说"这个问题我没直接做过，但我的理解是……"——比硬编一个答案好一万倍。应届生的通行证是学习能力，展示它。

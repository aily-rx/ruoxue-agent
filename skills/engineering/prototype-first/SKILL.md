# 原型先行

**核心信念**：跳过原型直接编码，返工时间翻倍。

量化依据（来自 4 个 Phase 的实际开发数据）：

```
有原型 + 架构设计:
  需求对齐 + PRD      20%
  原型 + 架构设计      30%   ← 最容易被跳过，但最重要
  编码实现            40%
  联调修正            10%

跳过前两步:
  编码实现            60%
  反复修改 + 返工      40%   ← 翻倍
```

## 步骤

### 1. 画原型 — 覆盖全部 6 种状态

```
必须覆盖:
  ✅ 默认状态     用户第一眼看到的样子
  ✅ 加载状态     等待数据时的过渡
  ✅ 空状态       无数据时的占位
  ✅ 错误状态     网络异常/服务不可用
  ✅ 展开状态     面板/弹窗打开时
  ✅ 移动端状态   响应式布局变化（<768px）
```

### 2. 标注三层信息

```
L1 结构: 组件名、DOM id、CSS class
L2 尺寸: px、vh、%、calc()
L3 交互: 点击/拖拽/键盘快捷键、动画方向

示例:
┌──────────────────────────────────────┐
│ ChatPanel                    [麦克风] │ ← Header (56px)
├──────────────────────────────────────┤
│                                      │
│  [AI 气泡]  你好！今天我能帮你什么？   │
│                                      │
│              你好，我想问个问题 [用户] │ ← 消息区 (flex:1, overflow-y:auto)
│                                      │
├──────────────────────────────────────┤
│ [输入框___________________] [发送]   │ ← InputBar (60px)
└──────────────────────────────────────┘
```

### 3. 拆组件树

从原型图反推组件层级和每个组件的 props/state：

```
App.tsx
├── Live2DCanvas (左侧)
└── ChatPanel (右侧)
    ├── MessageList (flex: 1)
    │   └── ChatBubble[] (每条消息)
    ├── VoiceButton (底部右侧)
    └── InputBar (底部)
        ├── Textarea (auto-resize, max 120px)
        └── SendButton / StopButton (toggle)
```

### 4. 定协议

原型画完后，前后端对齐数据协议（SSE 事件格式、HTTP 请求/响应 schema）。

## 反模式

- **只画默认状态** — 用户遇到加载/错误/空数据时页面是什么样？不画就不知道
- **画了布局没标尺寸** — "上面放个 Header"不够。Header 多高？56px 还是 64px？
- **前后端没对齐协议就各自开工** — 联调时才发现字段名不一致
- **画原型用 UI 设计工具而不用 ASCII** — ASCII 可以直接贴在 PRD 里，零上下文切换

## 适用场景

- 新页面开发（任何涉及 UI 的 feature）
- 前后端联调（协议必须先对齐）
- 复杂交互（多状态切换、动画、响应式）
- 重构现有页面（先画现状图，再画目标图）

## 症状

1. **初始表情不正常** — 模型加载后的默认表情与预期"中性"不一致
2. **说话后表情不恢复** — 回答播放完毕后，表情未回到中性
3. **表情切换生硬** — 从一个表情切换到另一个时出现"跳变"效果

## 根因分析

### Bug 1: Neutral 过渡的 intensity 缩放陷阱

**调用链**: `audio.onended` → `scheduleEmotionReset` → `setEmotion('neutral', 0.3)` → `transitionTo('neutral', 0.3)`

v1 代码走两阶段过渡:
- Phase 1 (100ms): 所有 params → 硬编码 `0`
- Phase 2 (500ms): 所有 params → `neutralParams[p] × 0.3`

`ParamEyeLOpen` 的实际路径:
```
当前值 = 1.0 (来自上一表情)
Phase 1: 目标 = 0 → 眼睛闭拢 (100ms)
Phase 2: 目标 = 1.0 × 0.3 = 0.3 → 眼睛只开 30%
```
**结果**: 数字人"半闭眼"状态，看起来没睡醒。

**核心错误**: 
1. Phase 1 设为 `0` 但中性值不是 `0` (眼睛中性 = 1.0 全开)
2. "50% 中性"无意义 — intensity 不应缩放 neutral

### Bug 2: Neutral 走两阶段过渡是设计错误

两阶段设计 = 先 snap 到 neutral → 再展示新表情。目标就是 neutral 时:
```
Phase 1: happy → neutral (100ms snap — 有意义)
Phase 2: neutral → neutral (500ms — 白跑，且 params 被重新赋值)
```
语义上无意义，且 Phase 2 可能引入新的参数值错误。

### Bug 3: 表情预设（Expression Preset）瞬时生效 vs. 参数平滑 lerp 冲突

```typescript
// transitionTo(): 表情预设立即以权重 1.0 生效
this._applyExpression(cfg.expressionIndex);  // ⚡ 瞬时

// update(): 参数逐帧 lerp（easeInOutCubic, 100-500ms）
this._model.setParameterValueById(id, lerpedValue);  // 🐢 平滑
```

**视觉效果**: 表情预设修改的眼形/光效瞬跳，嘴巴/眉毛平滑过渡。两个系统时间线不同步 → 用户感知"生硬"。

## 修复方案

### 修复 1: Neutral 单阶段 + 跳过 intensity

```typescript
if (emotion === 'neutral') {
    for (var p in tgtParams) {
        _paramFrom[p] = _paramCurrent[p];   // 从当前位置出发
        _paramTarget[p] = tgtParams[p];     // 完整中性值（不乘 intensity）
    }
    _transitionMs = cfg.transitionMs;       // 500ms 单阶段
    _phaseTwo = null;                       // 跳过两阶段
}
```

### 修复 2: Phase 1 目标改为真实中性值 (非 0)

```typescript
var neutralParams = CONFIG['neutral'].params || {};
for (var p in tgtParams) {
    _paramTarget[p] = neutralParams[p];     // 眼睛→1.0, 嘴→0, 眉→0
}
```

### 修复 3: 表情预设延迟到过渡结束后

```typescript
// transitionTo(): 只记录, 不执行
this._targetExpressionIndex = cfg.expressionIndex;

// update() 每帧: 过渡完成才一次性应用
if (t >= 1.0 && _targetExpressionIndex !== null) {
    _applyExpression(_targetExpressionIndex, 1.0);
    _targetExpressionIndex = null;
}
```

> 权衡: 放弃两阶段 "snap→target"，改为 "直接 lerp A→B + 末梢 preset"。
> 过渡全长由 `cfg.transitionMs` 控制 (200-500ms)。

## 关键经验

- **intensity × neutral = 语义错误** — 中性表情不做强度缩放
- **"设为 0" 是重复性陷阱** — 模型的自然中性值由设计师定义 (如眼睛=1.0)，已在 white-rectangle / ghosting 文档中强调过
- **Instant preset + smooth lerp = 视觉分裂** — 所有驱动同一面部的系统必须时间对齐
- **两阶段过渡不适配 neutral 目标** — 需按目标类型走不同代码路径
- **hot-reload ≠ 状态重置** — EmotionDriver 在 `useLive2D` mount 时初始化，改 TS 后需刷新页面

## v2.1 补充：表达式预设参数未覆盖的根因 (2026-07-24)

### 症状

neutral 过渡后腮红消失（ParamCheek → 0）但眼睛和眉毛不恢复——仍残留上一表情的眼形曲线（smile/form/angle）。

### 根因

表情预设通过 `doUpdateParameters` 以 **Add** 模式修改参数，例如：
- `exp_02` (happy): `ParamEyeLSmile += 1`, `ParamEyeRSmile += 1`
- `exp_05` (sad): `ParamBrowLAngle += -1`, `ParamBrowRForm += -1`
- `exp_08` (angry): `ParamEyeLForm += 1`, `ParamMouthAngryLine += 1`

这些参数**不存在于原来的 `neutral.params` 中**，所以 Phase 1 切换到中性时不归零。又因为它们是 Add 模式（非 Multiply），调用 `_applyExpression(0)`（透传表达式）也不会消除——加 `0` 无效果。

**Phase 1 只迭代 `tgtParams`（新表情参数）而非全部中性参数**，进一步放大了问题：

```
happy → sad:
  Phase 1 驱动: {ParamMouthDown, ParamMouthUp, ParamEyeLOpen, ParamEyeROpen}
  ❌ 未驱动: ParamEyeLSmile(1), ParamEyeRSmile(1) → 残留
  ❌ 未驱动: ParamCheek(0.5) → 残留
  
  结果: sad 嘴巴 + happy 眼睛 = 诡异表情
```

### 修复

1. **neutral config 覆盖全部 28 参数中可能被表达式修改的 22 项**（新增 13 个）：
   - `ParamEyeLSmile/RSmile: 0` — 重置 exp_02/04 笑眼
   - `ParamEyeLForm/RForm: 0` — 重置 exp_08 怒眼
   - `ParamEyeEffect: 0` — 重置 exp_04 眼星光
   - `ParamEyeBallForm: 0` — 重置 exp_07
   - `ParamBrowLAngle/RAngle: 0` — 重置 exp_05/06 眉角度
   - `ParamBrowLForm/RForm: 0` — 重置 exp_05/06/07 眉形状
   - `ParamMouthAngryLine: 0` — 重置 exp_08 怒嘴线
   - `ParamI/U/E/O: 0` — 安全兜底

2. **Phase 1 改为迭代全部 `neutral.params`**（非 `tgtParams`）：
   ```
   for (var p in neutralParams) { ... }  // 而非 tgtParams
   ```
   确保上一表情的所有残留一次性清除。

### 关键经验

- **"透传表达式"不可靠** — `Add=0` 不消除前置 Add 值，必须显式 setParameterById
- **Phase 1 范围决定表情纯净度** — 只重置新表情参数不够，必须重置全部中性参数
- **neutral.params 应包含所有可能被外部修改的模型参数** — 作为安全的"还原点"

## v2.2 补充：同帧竞态导致 Phase 2 目标被立即清空 (2026-07-24)

### 症状

v2.1 之后所有非 neutral 表情（thoughtful, sad, happy 等）完全失效——数字人面无表情。

### 根因

`update()` 中的两个检查在同一帧内触发：

```
Frame N (Phase 1 完成, t=1.0):
  1. lerp all params → OK
  2. Phase 2 trigger:
     _phaseTwo = null        // ← 清空！
     _paramTarget = {...}    // ← 写入 Phase 2 目标值
     _transitionMs = 450
  3. Expression check:
     t >= 1.0      → TRUE   (还是 Phase 1 的 t)
     !_phaseTwo    → TRUE   (刚在步骤 2 被清空！)
     _targetExpressionIndex !== null → TRUE
     
     → _applyExpression → 立即清空 _paramTarget ← 删掉了步骤 2 刚写入的目标！

Frame N+1:
  _paramTarget 为空 → 无任何参数被驱动 → 表情完全静默
```

**关键**：Phase 2 在步骤 2 把 `_phaseTwo` 置 null，而步骤 3 用 `!_phaseTwo` 判断"过渡全部完成"，两个条件在同帧满足 → 误判。

### 修复

**交换两个检查的顺序**——表达式/清理检查必须在 Phase 2 触发之前：

```
Frame N (Phase 1 完成, t=1.0):
  1. lerp all params → OK
  2. Expression check:
     t >= 1.0      → TRUE
     !_phaseTwo    → FALSE  (Phase 2 还在！)
     → SKIP ✓
  3. Phase 2 trigger:
     _phaseTwo = null
     _paramTarget = {...}    // 安全写入
```

Phase 2 的参数在整个第二阶段中正常 lerp，直到 Phase 2 的 `t >= 1.0` 时才触发清理。

### 关键经验

- **同一帧内状态变更+条件检查 = 竞态** — 清空标志后立即检查"是否已清空"是经典陷阱
- **检查和状态变更的顺序决定语义** — 先检查"是否还有工作未完成"，再做清理
